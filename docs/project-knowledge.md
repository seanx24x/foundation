# Project knowledge

Foundation 0.44 brings accepted decisions and captured issues together in Understand → Knowledge. M4.06 is verified and installed. See the [native and installation evidence](../artifacts/verification-v0.44.md).

## Find and follow

Search locally across titles, rationale or reported outcome, feature, screen, scenario and linked source paths. Filter by kind, feature and current, historical or unavailable status. Search reads the existing bounded project journals: up to 32 decisions and 32 issues. It does not create a second copy of the records, index remote content or contact an AI provider.

A selected record retains its original source hashes and evidence. Related records show a shared feature, shared source paths, or the same retained evidence identity and digest. These are navigational relationships; they do not establish causation. Existing source and comparison/observation actions retain their canonical validation, and images load only when explicitly requested.

Current decisions, stale or superseded decisions, undone changes, historical issues and unavailable evidence remain distinct. A saved report stays readable when its supporting evidence is unavailable. Storage failures retain their existing recovery action; searching never repairs or rewrites a journal implicitly.

## Use in Assistant

**Use in Assistant** prepares one selected record in the current conversation. The host resolves that exact record from the project journal, validates its digest and active feature, rechecks source/evidence availability, then waits for the Assistant to acknowledge the selection. The current prompt, source selections and mode are preserved. The action sends no provider request.

Existing context limits remain in force: up to four current decisions and one captured issue. A different selected issue is never replaced silently. Prepared investigation, revision, check or alternative-generation context must be resolved before adding knowledge. Decisions must remain applied, current and unsuperseded; historical issues can be shared with their explicit freshness assessment. The request disclosure and sent turn retain the exact selected snapshot. Source or context changes during dispatch still reject the request.

## Continuity and boundaries

Query, filters and selected record restore for the same project. Restoration never adds Assistant context, starts a runtime, loads captures, rewrites evidence or sends a request. The far-right Assistant remains independently collapsible.

This increment unifies existing local records. Freeform knowledge documents, semantic retrieval, automatic memory, team sharing, external issue trackers and cross-project search remain future work. Laptop and physical-display acceptance stay paused at the user's request.
