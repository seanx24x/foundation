# Foundation product checklist

Authoritative running checklist · Started 28 October 2026 · Current increment: M5.02 verified; M5.03 next; Foundation 0.47 installed; hardware acceptance paused at user request; M0/M1 release gates remain open

## Delivery contract

Design engineers first; macOS / Code OSS; React/Vite before SwiftUI and React Native. Direct provider API keys, with **OpenAI and Anthropic required from M1**. Local history/indexing, explicit AI context, guarded source changes and separate publishing/deployment control remain defaults.

Statuses: **Not started**, **In progress**, **Implemented—unverified**, **Verified**, **Paused**, **Blocked**. Parent capabilities are Verified only when all acceptance criteria have demonstrated evidence. A fixture, a source review and an installed-app check are different evidence. Unknown outcomes and absent credentials remain explicit. No item is silently removed when milestones change.

Each increment updates the child-task ledger and handoff below. Existing implementation references: [0.9 verification](../artifacts/verification-v0.9.md), [clarity audit](clarity-pass.md), [product principles](product-principles.md). Partial functionality is never full completion credit.

## Milestones and dependencies

- **M0 — Inventory and baseline:** complete traceability and measured local baselines before claiming improvements.
- **M1 / 0.10 — Connected web foundation:** running Vite targets, mapped selection, request observations, explicit Assistant context and both providers; depends on M0.
- **M2 — Daily coding and task execution:** feature working sets, deeper intelligence, inline assistance, all four AI intents, isolated multi-file changes; depends on M1 contracts and trustworthy ownership.
- **M3 — States, impact and visual review:** reproducible scenarios, paired captures, scope/consumer inventory and independent checks; depends on M1 runtime identity and M2 change groups.
- **M4 — Alternatives and project knowledge:** comparable branches, reproducible issue artifacts and revision-aware accepted decisions; depends on M2 isolation and M3 scenarios.
- **M5 — Platform expansion and release quality:** independent SwiftUI/Expo gates, compatibility/performance, signed distribution and updates; inherits proven workflows, not web capability claims.
- **M6 — New visual and motion system, then app-wide application:** create a brand-new, comprehensive Foundation visual and motion system from first principles, then apply it across the finished app. This remains the final milestone after the remaining M0–M5 work and acceptance gates, elevating clarity, usability, consistency and premium craft across every surface and end-to-end workflow.

E05 and P01–P07 are release gates in every milestone. Platform breadth never substitutes for a complete verified workflow.

## Scope of the first connected increment

The new adapter uses actual project Vite builds and a separate local API fixture. Existing saved-source sandbox remains an explicitly separate mode. Runtime mapping is instrumented; ambiguous/unavailable mappings do not authorize edits. Request timeline observations are not automatically causal traces. Server internals are unknown unless separately instrumented. Preview compilation, project checks, interaction and visual inspection remain independent.

Both direct provider adapters are required. Model selection is explicit; no silent fallback or automatic additional context. M1 retains one-file proposals and user-controlled Apply/Undo. Tool execution and multi-file isolation belong to M2. Local models and supported coding-agent integrations remain future extension options, not substitutes for the selected direct-provider requirement.

**M6.02 — create a brand-new visual and motion system:** establish a new visual identity, design specification, token architecture, component library and motion language. The [current specification](design-system.md), [tokens](../design/foundation.tokens.json) and [reference](../artifacts/design-system-v1/index.html) are migration records only. This is a new system, not an extension, consolidation or refinement of the existing one. The new system becomes authoritative when applied in M6.01.

- **Foundations and tokens:** establish the new visual identity and product/interaction principles; semantic light/dark colors; complete typography recipes; 4px layout grid and snapping; spacing, sizing, radii, borders, elevation and density; window/panel constraints and responsive layouts; icon and asset rules with retained license notices. Define mappings for native host and supported platform surfaces.
- **Component and pattern library:** design, specify and implement new reusable primitives, navigation, editors, inspectors, dialogs, feedback, AI chat/artifacts, runtime controls and review patterns. Document anatomy, variants, states, content rules, keyboard behavior, accessibility and when to use each pattern.
- **Motion system:** create a coherent new motion language with semantic motion tokens, durations, easing and permitted spring behavior; choreography and spatial continuity for entry/exit, expansion, panel resizing, selection, navigation, drag/scrub and progress. Specify interruption, reversal, cancellation, gesture tracking, focus/scroll continuity and reduced-motion equivalents. Keep input immediate and document measurable responsiveness and animation-performance budgets.
- **Interactive reference and documentation:** create a new standalone reference with inspectable component/state examples and runnable motion examples, including interruption and reduced motion, in both themes and supported densities/sizes. Connect examples to canonical tokens and implementation guidance, with realistic populated workflows and explicit native platform differences.
- **Adoption and maintenance:** maintain a component inventory, coverage matrix, versioned changes, migration guidance and recorded exceptions. Validate token usage, rendered geometry, contrast, accessibility and motion behavior; verify the new reference against its specification and define an explicit migration map before app-wide application.

**M6.01 — apply the new system across the app, then verify the complete experience:**

- **Every surface and complete journey:** onboarding and setup, project navigation, native editing, Understand, Refine, Review, runtime previews, inspectors, the far-right Assistant and all AI artifacts, Knowledge, search, commands, terminals, diagnostics, settings, dialogs and recovery. Include transitions between surfaces and all supported platforms.
- **Content, layout and structure:** remove superfluous content, clarify labels and actions, simplify navigation and task flows, strengthen hierarchy and progressive disclosure, and make scope, status and next steps understandable.
- **Visual language:** replace existing presentation with the new system's typography, color, contrast, iconography, spacing, 4px layout grid, alignment, radii, borders, elevation, density, window and panel sizing, resizing and responsive behavior. Apply the new Foundation design system consistently in light and dark themes, with the craft benchmark established by Apple, Linear and Vercel and a distinct Foundation identity.
- **Interaction and motion:** apply the new interaction and motion language to selection, focus, keyboard shortcuts, direct manipulation, feedback, transitions and interruption. Preserve spatial continuity, editor responsiveness, drafts and context; honor reduced motion.
- **Complete states and accessibility:** inspect normal, hover, focus, selected, disabled, loading, empty, disconnected, ambiguous, stale, failed and recovery states. Verify keyboard access, screen-reader semantics, contrast, enlarged UI and narrow panels in both themes.
- **Acceptance in the finished app:** retain a surface/state coverage matrix and before/after captures at representative window sizes; walk through complete workflows with representative design engineers without facilitator guidance; resolve findings and obtain the user's final visual/UX review. Builds and automated tests support acceptance alongside direct rendered inspection and interaction evidence. Reverify affected native workflows, packaging and recovery against the build with the new system applied.
