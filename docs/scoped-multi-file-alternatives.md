# Scoped multi-file alternatives

M4.02b extends retained comparison to a completed AI Build group. Foundation keeps the original conversation intact and gives each adopted result its own local source checkpoint. Foundation 0.40 is verified and installed. See [native and installation evidence](../artifacts/verification-v0.40.md).

## Scope

A candidate contains the entire current, unapplied group: two to eight existing application files, at most 64 KiB of source on each side in aggregate. Every changed and context path must already belong to the active feature and use a supported application-source path. Configuration, manifests, locks, hidden or generated files, dependencies and known Foundation runtime instrumentation are excluded. Partial selections must return to the whole proposal first. New/deleted files remain outside this increment. Explicit two-candidate generation is defined in [M4.05](ai-alternatives.md); autonomous generation remains outside scope.

## Workflow

1. Build a genuine group in Assistant using explicit source context. Select its saved feature and an instrumented screen/scenario.
2. In Review, name the alternative and choose the registered recipe and requested conditions. Preparing creates two owned copies and does not edit the original project.
3. Run both copies. Each observation retains the complete frozen feature source hashes, independent runtime session, recipe result and optional capture.
4. Repeat with another Build group against the same saved baseline, then compare compatible retained results. Foundation does not select a winner.
5. Explicitly discard the active proposal/group before choosing **Review this group**. Foundation validates private source copies, original baseline, every file hash and saved scope. It creates a new local group labeled **Retained alternative**, opens a native source diff, and leaves project files unchanged.
6. Inspect each file, then explicitly **Apply all** or discard. **Undo all** checks exact applied targets. A failed/interrupted batch retains a durable recovery checkpoint.

Adoption has no fabricated conversation or provider request. Local alternatives do not support refinement, version activation, partial acceptance or execution checks in this increment. A changed source, dirty contributing file, altered scope, cancelled operation or unavailable provenance blocks Apply. An unrelated draft remains unsaved and untouched.

## Evidence and write boundaries

The four-record capacity and single-token workflow remain supported. Token and group results may be compared only when baseline, frozen scope, recipe/catalog and requested conditions match. Historical compatibility does not grant permission to change the current checkout.

Private candidate metadata retains its original Build artifact; ordinary snapshots contain paths and hashes, never source bodies. Review and initial Apply verify both copies and retained metadata. Immediately before each serialized rename and at completion, validation checks the entire original inventory with only exact owned progress normalized: already-written target hashes and pinned temporary file path/device/inode/content. No renderer supplies file exceptions.

Writes are atomic per file, serialized across the group. They are not an atomic multi-file transaction. Existing journal recovery and exact target reconciliation remain authoritative. Undo/recovery can preserve later unrelated changes without requiring the entire original project baseline.

Compilation, observed interaction, captures, visual assessment and source-to-pixels correspondence remain separate. This workflow records compilation as **Not recorded**, visual assessment as **Not assessed**, and source relationship as **Unverified** unless independently established. Restoring history starts no runtime, provider request, source application or image read.

## Acceptance checklist

- [x] Shared strict source/basis contract; original AI digest compatibility preserved.
- [x] Independent copies and complete feature-source evidence for every changed file.
- [x] Native genuine Build groups, compare results, both file diffs and separate Apply/Undo.
- [x] Source/context drift, drafts, cancellation, storage failure and batch recovery covered.
- [x] Local provenance visible; unsupported partial/refine/version/check actions blocked.
- [x] Second-process restoration without automatic work; unrelated draft preserved.
- [x] Signed candidate payload verified, installed, and normal Orbit state preserved.

Laptop and physical input/display acceptance remain paused at the user's request.
