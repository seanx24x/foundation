## Results

- **207 project tests and 681 desktop tests pass**, with no failures or skips. Both TypeScript targets, JavaScript syntax and whitespace checks pass. Focused backend, host, UI/model and runtime counts are 207, 19, 126 and 13; they overlap the full suites.
- All three existing provider text protocols are covered. Unsupported checks, command fields, native tool calls, malformed and incomplete responses cannot become actionable recommendations. Zero-check advice remains valid; users may explicitly choose supported checks themselves.
- Preparation and restart contact no provider. Shared input includes the editable user instruction, the original selected Build source basis with staged edits overlaid, and fixed advertised check IDs/labels. Discovered test filenames, commands, prior tool output, environment and unrelated history are excluded. The packaged fixture verifies private filename, stdout and environment markers are absent, along with command and binding fields.
- Packaged acceptance spans three native processes and exactly two loopback provider requests: Build and the explicitly sent check suggestion. An unadopted recommendation restores first; a fresh matching workspace permits edited TypeScript→Node adoption without execution. A separate explicit Run passes TypeScript and leaves Node pending. The third process restores that exact decision without work; explicit Run then passes Node in a distinct isolated attempt.
- Immutable recommendation provenance survives adoption and restart. Repeated Save cannot create another plan. Save/Dismiss races, failed storage, stale source, changed copy, ownership loss, Stop and late completion are covered. Accepted history opens the linked plan instead of creating a replacement.
- All eight packaged workflows pass: AI suggestions, saved check plans, staged-group revision, request revision, isolated execution, layout/context restart, grouped Apply/Undo and 17 editor checks.
- A cancellation test was synchronized with the server observing client closure. The full suite also exposed an existing hard-page-close timing dependency; acknowledged pagehide ownership and exact lease expiry at 7,999/8,000 ms are now tested separately. No production runtime or cancellation timeout was changed. The final full suite passes at default concurrency against the signed candidate. The staged-group revision, request revision, execution and grouped Apply/Undo native drivers now recheck exact mode, prompt and selected source before a bounded retry of pre-key focus refusal; they never retry after keyboard dispatch. A separate initial check-plan activation lost focus before Space reached Send; no request was made. Its driver now observes stable enabled focus and exact request inputs before one dispatch. A renderer diagnostic confirms enabled Send focus survives valid state updates, but the failed trace cannot distinguish temporary disabled context from a late explicit focus message; no production focus change was justified.
