# Foundation 0.34 — condition matrices

M3.03d adds explicit width × application theme × motion matrices to the React/Vite adapter. Choose one app-authored recipe and 1–12 conditions. Each condition opens a fresh runtime document, starts its own observation, executes the bounded recipe, and optionally captures a local PNG. Stop or the first uncertain result prevents later cells from running.

## Verification

- 1,231 desktop tests passed with no failures or skips against the signed candidate; desktop TypeScript and syntax checks passed.
- Focused coverage includes 26 matrix host, 26 matrix journal and 9 matrix renderer tests, plus reserved observation-ID and actual capture-capacity checks.
- Exact preview acknowledgements, initial-save Stop, changed source/catalog/context, unavailable capture storage, write-acknowledgement recovery, both themes, compact full-frame Fit, keyboard focus and comparison navigation are covered.
- Native acceptance: four native matrix cases passed: eight width/theme/motion combinations, two optional captures, explicit Stop and deliberate callback failure. Twelve fresh documents produced twelve independent observations/replays and two verified PNGs. Three later cells stayed Not run. Saved comparisons, records and image bytes restored exactly in a second process with runtime idle and no provider requests..
- Installation: 28 installed payloads match the tested signed candidate; deep/strict signature passes. The previous 0.33 app is retained. Eight saved Orbit files and the original 727-byte draft are unchanged. Native relaunch restored ProfileForm preview/caret 59:1, Understand/relationships, Profile saving, Explorer, hidden bottom panel, far-right Assistant, task brief, SaveButton-only context, Ask and empty composer..

## Evidence boundaries

Replay completion reports callback outcomes. Every matrix observation remains **Not assessed**. Actual requests remain unattributed interval evidence. Captures retain actual viewport/media measurements with application theme, data and animation marked Unknown. Source-to-pixel correspondence remains Unverified. No automatic visual, behavioral, compilation or accessibility verdict is inferred.

A new document does not clear cookies, browser storage or backend state; app-authored preparation owns its named fixture. Unsupported adapters, full data/environment snapshots and isolated-alternative comparison remain open. Hardware/laptop/physical input acceptance remains paused at the user’s request; no endurance test was rerun.

The first native attempt is retained as a failed harness run: it expected the final requested dark theme after matrix completion, but Foundation correctly restored the saved Light preview preference. The corrected harness checks saved settings separately from each cell’s immutable requested and observed evidence; no production change was made for that assertion.

A second native attempt was correctly refused during capture because the matrix Fit calculation fed the canvas’s changing intrinsic height back into its scale. A deterministic regression reproduced a 2 px-per-frame shrink after acknowledgement. The fix derives the bound from the external viewport and CSS maximum height; native capture guards remain unchanged. The refused attempt and its original signed bundle are retained.

A subsequent native harness attempt reached recipe selection before the lazy disclosure control had a rendered box. The driver now waits for the visible enabled select and its requested option before using the normal select operation; no application behavior was changed. This failed attempt is retained separately.

The next attempt passed eight conditions, both PNG captures and Stop, then correctly blocked another matrix with the existing reload-required latch. The harness now explicitly activates Open screen and verifies a new connected document before selecting the next recipe. It does not bypass the latch.
